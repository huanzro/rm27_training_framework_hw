
## 一、全双工与半双工

全双工指物理上存在两套独立通路，而不是"协议允不允许回包"。SPI 的 MOSI 与 MISO 各一根，主机每输出一个时钟，从机同时在 MISO 上回一位，所以读寄存器也是"发一个字节、同时收一个字节"。

由此得到一个直接的推论：**发地址的那个字节期间收到的数据一定是垃圾**。从机要把整个地址字节收完才知道该吐哪个寄存器。后面那个哑元字节的 bug，根源就在这里。

SPI 本身也有单线半双工的变体（`SPI_DIRECTION_1LINE`），这里不用：全双工才能在**同一次传输**里完成"发地址 + 收数据"，CS 只翻转一次。HAL 侧也印证了这点——`HAL_SPI_TransmitReceive()` 只支持 `SPI_DIRECTION_2LINES`（`stm32f4xx_hal_spi.c:1155`）；本工程 `.ioc` 里 `HalAssertFull=false`，这个断言不生效，所以约束得自己保证。

## 二、SPI 的特点与配置

主机产生 SCK，主从各有一个移位寄存器，一个边沿交换一位，八个时钟换一个字节。从机靠片选被选中、靠 CPOL/CPHA 与主机约定采样边沿，没有地址也没有应答。

| | 全双工 | 半双工 |
| --- | --- | --- |
| 数据方向 | 两个方向同时能传 | 同一时刻只能一个方向 |
| 需要的线 | 收发各一根 | 一根分时复用 |
| 例子 | SPI、UART | I²C、RS-485、单线 UART |

优点是快（推挽输出，几十 MHz 常见）、协议极简、天然适合寄存器读写。代价是没有硬件寻址（每多一个从机多一根片选）、没有应答（从机没接上主机只会读到 `0x00` 或 `0xFF`，分不清"读错"和"没接"），也没有出错检测。

四个模式由 CPOL（空闲电平）和 CPHA（采样沿）组合：

| Mode | CPOL | CPHA | 采样时刻 |
| --- | --- | --- | --- |
| 0 | 0 | 0 | 第一个（上升）边沿 |
| 1 | 0 | 1 | 第二个（下降）边沿 |
| 2 | 1 | 0 | 第一个（下降）边沿 |
| 3 | 1 | 1 | 第二个（上升）边沿 |

Mode 0 与 Mode 3 的采样沿都是上升沿，区别只在 SCK 空闲电平高低——这就是很多从机两种模式都能通的原因。配错不会报错，只会整体错一位或全 0。BMI088 用 Mode 0。

**我的配置**（CubeMX → Connectivity → SPI1）：

| 项 | 值 | 依据 |
| --- | --- | --- |
| Mode | Full-Duplex Master | `.ioc`：`SPI1.Mode=SPI_MODE_MASTER`、`Direction=SPI_DIRECTION_2LINES` |
| Prescaler | **16** | `SPI1.BaudRatePrescaler=SPI_BAUDRATEPRESCALER_16`，这项是我显式改的 |
| Data Size | 8 Bit | `spi.c:43`（CubeMX 默认值） |
| First Bit | MSB First | `spi.c:48`（默认值） |
| CPOL / CPHA | Low / 1Edge = Mode 0 | `spi.c:44-45`（默认值） |
| NSS | Software | `spi.c:46`（默认值），片选走 GPIO |

`.ioc` 里 `SPI1.IPParameters` 只列了 `VirtualType,Mode,Direction,CalculateBaudRate,BaudRatePrescaler`——**没进这个清单一律是默认值**，所以除 Mode/Direction/Prescaler 外，上表其余几项都是回读生成的 `spi.c` 才敢写的，没只看面板。

**时钟**：SPI1 挂 APB2，`APB2CLKDivider=RCC_HCLK_DIV2`、`APB2Freq_Value=84000000`，于是 $84\ \text{MHz}/16=5.25\ \text{MHz}$，与 `.ioc` 的 `SPI1.CalculateBaudRate=5.25 MBits/s` 一致。不能随手选 /2：那会得到 42 MHz，远超 BMI088 的 10 MHz 上限（`BMI088.hpp:26`）。超频的症状不是报错，而是偶尔错一位，极难排查。

**引脚**：SCK=PB3、MISO=PB4、MOSI=PA7、CS_Accel=PA4、CS_Gyro=PB0。两处坑：调试口只能选 SWD，完整 JTAG 会占掉 PB3/PB4；不要用 SPI2 驱动板载 IMU，它的引脚（PB13/14/15）引到的是外部接口。

片选初值是 Set（不选中），并且**先写 ODR 再配成推挽输出**（`gpio.c:61`/`:64`）。顺序反过来会在上电瞬间产生一个 CS 负脉冲，而那时 SCK 还没配成 SPI 功能，BMI088 会被误选中一次。

**片选互斥**：加速度计和陀螺仪是同一封装里的两个独立 SPI 从机，共用 SCK/MOSI/MISO、各一根 CS，同时拉低就是总线冲突。所有读写都收敛到 `ReadReg`/`WriteReg`，片选在函数内部成对拉低拉高；BSP 再加一把自旋锁，拿不到锁时不强行进临界区，而是计一次 `SPI_LockTimeoutCount()` 并返回 `HAL_BUSY`——宁可丢一次传输，也不破坏互斥。手册要求两次访问之间 CS 保持高 ≥1 μs，代码里没加额外延时，靠函数返回与循环开销自然满足；**这条没有示波器实测过**，以后若把分频改小出现偶发错读，先回来查这里。

## 三、上板第一次：加速度计输出恒为零

现象很干净，根因却不在 SPI 时序上。连续 8 次采样（间隔 100 ms）读 `ACC_X_LSB` 起 6 字节，全部是 `00 00 00 00 00 00`；同一时刻芯片 ID `0x1E` 读得对、陀螺 `0x0F` 且在更新、温度 23.5 ℃、写进去的 `pwr_ctrl=0x04 / pwr_conf=0x00 / conf=0xAB` 回读全部成功、`err_reg=0x00`。

**SPI 通、配置生效、芯片活着，但测量输出恒为零。**

根因：加速度计上电默认是 I²C 模式，要靠一次 SPI 传输（CS 上的电平跳变）才切到 SPI。原实现在 `Config()` 开头做了一次哑元读完成切换，但紧接着写了 `ACC_SOFTRESET(0x7E)=0xB6`——**软复位把它打回了 I²C 模式**，复位后没有重切。陀螺不受影响，它是同一封装里的另一个 die，有独立 SPI 接口。

修法是在软复位并等 100 ms（`BMI088.cpp:674`）之后，再补一次哑元读和 5 ms 延时（`:687-688`）。烧录后 8 个采样从"完全相同"变成"互不相同"，输出恢复更新。

但数据仍然不对：模长 353~414 m/s²（应约 9.81）、温度 44 ℃（应约 23.5）。这说明还有第二个问题。

## 四、上板第二次：哑元字节错位（已修复）

问题出在**加速度计的读帧比陀螺仪多一级哑元字节**。陀螺仪的读帧是"地址 + N 字节"，数据从 `rx[1]` 开始；加速度计是"地址 + 1 字节哑元 + N 字节"，数据从 `rx[2]` 开始。原实现两者统一按 `rx[1]` 取，等于把加速度计的每个寄存器都读错了一格。

决定性的取证是从 `ACC_CONF(0x40)` 起一次连读 6 字节：

```
实际返回: 0x01  0xAB  0x01  0x00  0x00  0x46
          ↑     ↑     ↑
        哑元  ACC_CONF  ACC_RANGE
              =0xAB ✅  =0x01 ✅
```

真值整体比陀螺仪右移一个字节，而 `ACC_CONF=0xAB`、`ACC_RANGE=0x01` 说明**配置一直是写对的**——写时序不需要哑元，错的只是读的对齐。

这个 bug 隐蔽的原因：单字节读时只收两个字节（哑元 + 真值），代码取 `rx[1]` 拿到的是"下一个寄存器"的值，于是所有回读系统性错位；而 `ACC_CHIP_ID(0x00)` 恰好因为哑元就是真值而看起来完全正常，长期把问题掩盖成了"SPI 通信正常、配置已生效"。
